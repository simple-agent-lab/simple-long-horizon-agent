1 框架设计思想与我们的契合点

框架原则 两半分离 (Host + Container)

simple-agent-lab 核心架构是 Host half (Suite) + Container half (ContainerTask)。 Host 负责数据加载和编排，Container 负责任务执行。每个 bench 的 evals/{bench}/suite.py 和 src/.../suites/{bench}/container.py 正是这两个半。

我们如何契合 数据即配置

框架提倡 LaunchSpec 用数据表达差异而非 if-else。我们的每个 Suite 都通过 task_input() 返回纯 dict（无行为），通过 eval_inputs() 传递评分数据。 7 个 bench 的 LaunchSpec 全部统一为同一 image + workdir。

框架原则 容器无侵入

框架要求 不修改 benchmark image，通过 runtime injection 注入 agent 代码。 我们复用 clawbase-nanobot:v1 但删除了 NanoBotAgent 依赖，agent 运行时通过 simple-agent-lab 的 in-container runner 注入。

我们如何契合 评分正交分离

框架提供 3 种评分路径：(1) evaluate() hook 原地评分 (2) eval_inputs=None 留给 host-side judge (3) Oracle 模式。我们精确使用了前两种：pinchbench/clawbench_official/skillsbench/agentbench 用 evaluate hook， zclawbench/claweval 用 host-side judge，clawbench_tribe 用宿主评分。

框架原则 正交后端

框架通过 ContainerBackend (process/docker/remote) 和 ArtifactStore (local/http) 实现计算与存储的正交分离。我们的所有 bench 都同时兼容 --backend process 和 --backend docker， 零修改切换。

我们如何契合 自包含数据

每个 bench 的 evals/{bench}/data/ 包含完整任务数据，无运行时网络请求。 这与框架 "suite author 负责数据" 的设计一致。数据格式直接沿用原格式 (TOML/YAML/Markdown/JSON)， 无额外转换层。

4 各 Benchmark 集成详情
5 三种评分策略

策略 A In-Container evaluate()

Container half 实现 evaluate() 函数，框架自动在 agent 完成后调用。 评分逻辑在 container 内执行，可访问 workspace 文件系统。
适用: pinchbench (grade函数), clawbench_official/skillsbench (pytest), agentbench (结构检查)

策略 B Host-side Judge

Suite eval_inputs() 返回 None，跳过 in-container 评分。 评分在外部通过 LLM judge 完成，读取 trajectory.jsonl + rubric。
适用: zclawbench (category-based), claweval (comprehensive rubric)

策略 C Host-side Post-run

run_benches.py 中的 score_fn 在 run_suite_instance() 完成后执行。 直接读取 trajectory.jsonl 解析最后一条 assistant 消息，做字符串匹配。
适用: clawbench_tribe (简单 string match)

6 关键技术决策

路径映射: workspace/ → ./

ClawEvalkit 中任务指令写 workspace/references.bib 和 /root/scan_data.stl。 在 simple-agent-lab 中 workdir 就是 workspace 本身。Container 的 build_task() 中做字符串替换，确保 agent 看到正确的相对路径。

Transcript 格式转换

PinchBench 的 grade() 函数期望 NanoBot 格式的 transcript。 Container 的 _build_transcript() 将 simple-agent-lab 的 trajectory.jsonl 转换为 NanoBot 格式（role/kind/content blocks → type/message 结构）。

Pytest conftest 注入

clawbench_official 的 verifier 使用 @pytest.fixture workspace 从 --workspace option 读取路径。Container 的 evaluate() 动态生成 conftest.py 注册此 option，避免修改原始测试代码。

二进制文件传递

SkillsBench 有 .stl 二进制输入文件。由于 instance 经过 JSON 序列化（写入 instance.json）， 不能直接 embed bytes。改为传递 data_dir 路径，Container 的 build_task() 直接从 data dir 复制到 workspace。
