用户怎么触发评测？

🔑
python -m 的触发机制

-m 让 Python 在 evals/openclaw/ 下找 __main__.py。这个文件 import runner.main()，后者用 argparse 定义 CLI 参数，解析后调用 run_eval()（节点3）。

🔑
.env 加载方式

set -a 开启自动 export，source .env 加载本地未提交的 .env 里的 GPT_API_KEY= 等，set +a 关闭。这样 Python 的 os.environ.get("GPT_API_KEY") 就能读到。

💡
${1:+--sample $1} 是什么？

Bash 的 ${var:+word} 语法：如果 $1 非空则展开为 --sample $1，否则为空。这样 ./run_openclaw_pinchbench.sh 5 就只跑 5 个样本，不带参数则跑全量。

怎么实现断点续跑？

_build_azure_agent() — 构建自定义 AzureOpenAI Agent
SAL 不支持 AzureOpenAI，怎么绕过？
SAL 内置 Provider 只有 openai-chat / openai-responses / anthropic-messages / fake 四种，没有 AzureOpenAI。 所以手动构建 Agent：清代理环境变量 -> 创建 bash tool tuple -> 定义 generate 闭包（内部每次创建 AzureOpenAI client 调 ModelHub）-> 返回 Agent(generate=azure_generate)。 闭包内部完成完整的格式转换链：SAL Message -> LLMMessage -> OpenAI chat format -> API call -> response -> SAL Message。
闭包内部的一次 generate 调用 — 完整数据转换链6步转换

  ① messages_to_llm_messages(visible)        -> [LLMMessage, ...]
  ② tool_defs = [tool_to_llm_tool(t) for t in tools_tuple]

⚠️
tools_tuple 必须在闭包外创建

Python 闭包捕获的是变量引用而非值。如果 tools_tuple 在 azure_generate() 内部创建，每次调用时 tools_tuple 都会被重新绑定到新 tuple，导致闭包引用不到闭包外部的 tools 参数。

⚠️
AzureOpenAI 返回的 arguments 是 JSON 字符串

标准 OpenAI SDK 的 function.arguments 直接是 dict（Python SDK 已解析），但 AzureOpenAI SDK 保留原始 JSON 字符串。必须 json.loads() 转成 dict 后才能传给 SAL 的 ToolCallBlock。这是调试中最难发现的 bug。

💡
每个 turn 都重新创建 AzureOpenAI client

这是有意为之——简化连接管理，避免长连接超时。由于每次调用是独立的 HTTP 请求，性能影响可忽略。

agent.run() — SAL 核心执行循环
Agent 怎么执行任务？每轮循环做了什么？
agent.run(prompt, max_turns) 是 SAL 的核心循环（core.py L98-198），最多跑 max_turns 轮。 每轮：(1) 构建上下文（包含所有历史消息）；(2) 调 agent.generate(visible) 让 LLM 生成回复； (3) 如果回复包含 tool_call，执行 BashTool；(4) 把 tool 结果作为新消息加入上下文；(5) 如果 LLM 回复是 "final"，退出循环。 本质是一个 "思考 -> 行动 -> 观察" 的 ReAct 循环。

score vs passed 的区别

score 是 pytest verifier 返回的 weighted_score（0-1 浮点数），乘 100 后变成百分比。passed 是 verification.passed == True 的任务数（即所有 check 都通过）。一个任务可以 passed=False 但 score>0（比如 29/30 checks 通过）。

💡
为什么 details 不写入磁盘？

details 包含每个任务的完整 result dict（含长字符串 details 字段）。35 个任务的 summary JSON 带约 50KB details，单独的 result.json 总计约 35KB。写入磁盘的精简版只有 6 个字段，方便快速查看。
