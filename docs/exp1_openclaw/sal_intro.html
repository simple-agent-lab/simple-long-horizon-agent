Simple Agent Lab

一个面向学习和原型设计的轻量级 Agent 框架，采用 Balanced Message Runtime 架构，核心循环简洁可读，支持 SWE-bench 评测
Python Agent Framework SWE-bench 集成 Provider-Agnostic LLM Multi-Agent 委托 Docker 沙箱
TLDR: Simple Agent Lab 是一个文档优先、面向教学的 Agent 框架，核心设计理念是 "最小 Agent 循环 + 显式数据流"。它用 5 个核心组件（Agent + Message + State + ContextView + run()）驱动一个 Generator-based 运行时，支持 Bash 工具执行、多 Agent 委托、Provider 无关的 LLM 调用，以及 Docker 化的 SWE-bench 评测。

一句话概括

Simple Agent Lab 是一个 docs-first 的轻量 Agent 框架，面向高校学生、小团队和独立开发者，目标是让 Agent 的核心循环（Agent Loop）可以通过代码直接阅读和理解，而不需要面对复杂的框架抽象。

设计哲学

📖 文档优先

AGENTS.md / CONTEXT.md / CONTRIBUTING.md 等文档驱动开发，核心代码不超过几百行，可以完整阅读。

🔄 最小循环

Agent Loop 是一个 Generator，每轮：构建上下文 → 调用 LLM → 分发工具 → 检查终态。没有隐藏的框架行为。

🔗 显式数据流

所有消息走统一 ContentBlock 模型（TextBlock | ImageBlock | ThinkingBlock | ToolCallBlock | ToolResultBlock），没有隐式转换。

🌐 Provider 无关

LLM 层通过 Bridge 模式将 runtime Message 投影为 provider-agnostic 的 LLMMessage，支持 OpenAI / Anthropic / Fake 等多种后端。

Agent + Message + State + context_view() + run() = 完整 Agent 运行时

TLDR: run() 是核心 —— 一个 Generator 函数，每轮 yield 事件（Event），在每轮中：构建 ContextView → 调用 agent.generate(visible) → 记录输出 → 分发工具调用。当 agent 输出 kind="final" 时循环结束。整个过程是完全显式的，没有隐藏的状态机或回调。

Agent 数据类

@dataclass
class Agent:
    name: str              # agent 名称
    generate: GenerateFn   # 核心生成函数 (list[Message] → Message)
    role: str = ""         # agent 角色描述
    tools: tuple[AgentTool, ...] = ()  # 绑定的工具集
    context_policy: ContextPolicy | None = None  # 上下文策略

    def run(self, task, *, max_turns=10, abort=None):
        state = State(task=task)
        state.send("task", "user", self.name, task)
        events = run(self, state, max_turns=max_turns, abort=abort)
        return state, events

run() 主循环伪代码

def run(agent, state, max_turns=10):
    yield agent_start()
    for _ in range(max_turns):
        yield turn_start()

        # 1. 上下文压缩（可选）
        for evt in maybe_compress_context(agent, state, policy):
            yield evt

        # 2. 构建上下文视图（token 预算、裁剪）
        context = build_context_view(name, state.active_context_messages(), policy)

        # 3. 调用 LLM
        yield model_request(visible_messages, tools)
        output = agent.generate(visible_messages)
        yield model_response(output)
        state.record(output)

        # 4. 分发工具调用（支持并行/顺序）
        if output has tool_calls:
            for evt in dispatch_tool_calls(output, tools, state):
                yield evt

        yield turn_end()

        # 5. 终止条件
        if output.kind == "final":
            break

    yield agent_end(reason="done" | "max_turns")

工具分发 (dispatch_tool_calls)

工具分发支持 并行 和 顺序 两种执行模式：

  • 如果任何工具标记为 execution_mode="sequential"，则所有工具顺序执行
  • 否则使用 ThreadPoolExecutor 并行执行（最多 8 个并发）
  • 每个工具有独立的 timeout_seconds 和 abort 检查
  • 工具结果打包为单个 tool_results_message()（N 个 ToolResultBlock）
  • 支持 terminate 标志，工具可以主动终止循环

State 管理

@dataclass
class State:
    """Append-only 事件日志，支持快照缓存"""
    events: list[Event]

    def record(self, msg)      # 记录消息到 transcript
    def active_context_messages() → list[Message]  # 获取 agent 可见消息
    def agent_start()          # yield AgentStartEvent
    def turn_start/turn_end()  # yield TurnStartEvent / TurnEndEvent
    def model_request/response()  # yield Model*Event
    def tool_execution_*()     # yield ToolExecution*Event
    def agent_end(reason)      # yield AgentEndEvent

State 是 append-only 的，所有变更都通过事件记录。StateSnapshot 提供快速缓存访问。

ContextView 投影

📊 ContextPolicy
@dataclass
class ContextPolicy:
    max_tokens: int = 4096
    trim_from: str = "bottom"  # 裁剪方向
    reserve_for_response: int = 1024
🔍 build_context_view()

将完整的 transcript 投影为 agent 可见的消息列表。基于 token 预算裁剪，优先保留最近的对话。支持消息级压缩。

TLDR: 工具系统设计极简 —— 每个 AgentTool = Tool 定义 + execute 函数 + 执行模式。内置两个核心工具：bash（本地 Shell 执行，支持超时/截断/图片附加）和 task（多 Agent 委托，父 agent 选择子 agent，子 agent 的 final 消息作为 tool result 返回）。

Bash 工具

💻 bash.py — 本地 Shell 执行
def make_bash_tool(*, cwd=None, timeout=300, max_output=100000):
    return AgentTool(
        name="bash",
        description="Run bash commands",
        parameters={...},  # JSON Schema
        execute=fn(tool_call_id, args, abort, on_update),
        execution_mode="sequential",
        timeout_seconds=timeout,
    )

核心特性

  • 超时保护：默认 300s，最大可配，超时自动终止
  • 输出截断：max_output_chars 控制输出大小，超出截断并提示
  • 图片附加：支持 attach 参数，将图片文件转为 ImageBlock 附加到结果
  • sleep 检测：detect_blocked_sleep_pattern() 检测无意义的 sleep 调用
  • Abort 检查：每条命令执行前检查 abort 标志

Task 工具 — 多 Agent 委托

🧠 task.py — 多 Agent 委托
def task_tool(agents: list[Agent]) -> AgentTool:
    return AgentTool(
        name="task",
        description="Delegate to a sub-agent",
        parameters={
            "subagent_type": {"enum": [a.name for a in agents]},
            "prompt": {"type": "string"},
        },
        execute=fn(call_id, args, abort, on_update):
            # 1. 从 agents 中选择 subagent_type 对应的 agent
            # 2. sub_agent.run(args["prompt"])
            # 3. 子 agent 的 final 消息作为 tool result 返回
    )

这使得多 Agent 流程的表达方式是：父 agent 通过 task tool 委托给子 agent，子 agent 独立完成自己的 run() 循环后，final 消息作为父 agent 的 tool result 返回。

Bash Agent 预设

BASH_AGENT_SYSTEM_PROMPT = (
    "You are a tiny bash-use agent. Use the bash tool to satisfy the task "
    "— parallel tool calls are fine when the steps are independent, and "
    "set `attach` on the call when you want to surface an image file. "
    "After the tool_result, return a short final answer."
)

def make_bash_agent(provider, *, cwd=None) → Agent:
    return make_llm_agent(
        name="bash_agent",
        provider=provider,
        tools=[make_bash_tool(cwd=cwd)],
        system_prompt=BASH_AGENT_SYSTEM_PROMPT,
        target="user",
    )

这是 SWE-bench 评测的核心 agent —— 一个"用 bash 解决任务"的最小预设。

关键实现细节

Wheelhouse 机制

预先下载所有依赖 wheel（包括 simple-agent-lab 自身和 anthropic/openai SDK），容器内通过 --no-index --find-links 离线安装。支持增量更新（每次运行重建项目 wheel）。

环境隔离

API Key 通过 Docker environment 注入（OPENAI_MODEL, OPENAI_AUTH_TOKEN），不写入容器文件系统。支持 --network-mode host 等网络配置。

实例清理

加载 instance 时自动去除 patch, test_patch, FAIL_TO_PASS 等私有字段，防止模型看到答案。

API 兼容

支持 openai-chat 和 openai-responses 两种 API 模式。通过 OpenAI 兼容接口可以接入任意 LLM 后端。

数据流（PinchBench 为例）

1. 从 ClawEvalkit benchmarks/pinchbench/tasks/ 加载任务（解析 YAML frontmatter + Prompt + grade_code）
2. 构建 SAL Provider（从 ClawEvalkit configs/models/ 读取模型配置，映射 provider → ApiKind）
3. 创建 Bash Agent，在隔离 workspace 中运行
4. 将 SAL 事件转换为 ClawEvalkit transcript 格式（MessageEvent → message dict, ToolExecution → tool_call/tool_result）
5. 执行任务的 grade_code（内嵌 Python 函数），计算评分
6. 保存结果到 outputs/pinchbench/{model}/{task_id}/result.json
